---
title: "Handoff mechanism"
description: "How supervisor agents delegate tasks to specialized sub-agents using tool-based handoffs."
---

The supervisor delegates work to sub-agents by calling **handoff tools** — ordinary LangChain tools that, when executed, return a LangGraph `Command` object directing the graph to route execution to a specific sub-agent node.

## How handoffs work

When the supervisor LLM decides to delegate a task, it emits a tool call targeting the appropriate handoff tool (e.g., `transfer_to_math_expert`). LangGraph's `ToolNode` executes the tool, which returns a `Command` that:

1. Sets `graph=Command.PARENT` so the command propagates up to the supervisor's parent graph.
2. Sets `goto` to the name of the target sub-agent node.
3. Carries a `update` dict (for single handoffs) or a `Send` object (for parallel handoffs) containing the messages to pass to the sub-agent.

The graph then routes to the named sub-agent node, runs it to completion, and returns control to the supervisor.

## `create_handoff_tool`

`create_handoff_tool` is the factory function that produces a handoff tool for a given sub-agent:

```python
from langgraph_supervisor import create_handoff_tool

handoff = create_handoff_tool(
    agent_name="math_expert",
    # name and description are optional
)
```

**Parameters:**

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `agent_name` | `str` | required | Name of the target sub-agent node in the graph |
| `name` | `str \| None` | `None` | Custom tool name. Defaults to `transfer_to_<agent_name>` |
| `description` | `str \| None` | `None` | Custom tool description. Defaults to `Ask agent '<agent_name>' for help` |
| `add_handoff_messages` | `bool` | `True` | Whether to add `(AIMessage, ToolMessage)` markers to the message history |

### Default tool naming

When no `name` is provided, the tool name is derived from the agent name using the `transfer_to_` prefix:

```python
# agent_name="math_expert"  →  tool name: "transfer_to_math_expert"
# agent_name="Research Agent"  →  tool name: "transfer_to_research_agent"
```

The agent name is normalized before being used in the tool name: leading/trailing whitespace is stripped, internal whitespace sequences are replaced with `_`, and the result is lowercased.

### Custom tool names and descriptions

```python
from langgraph_supervisor import create_handoff_tool, create_supervisor

workflow = create_supervisor(
    [research_agent, math_agent],
    tools=[
        create_handoff_tool(
            agent_name="math_expert",
            name="assign_to_math_expert",
            description="Assign task to math expert",
        ),
        create_handoff_tool(
            agent_name="research_expert",
            name="assign_to_research_expert",
            description="Assign task to research expert",
        ),
    ],
    model=model,
)
```

<Warning>
  When you supply custom handoff tools, you must provide one for **every** sub-agent passed to `create_supervisor`. Omitting any agent will raise a `ValueError`.
</Warning>

## The `handoff_tool_prefix` parameter

If you want to rename all automatically generated handoff tools without creating them manually, use the `handoff_tool_prefix` parameter on `create_supervisor`:

```python
workflow = create_supervisor(
    [research_agent, math_agent],
    model=model,
    handoff_tool_prefix="delegate_to_",
)
# Creates tools named: delegate_to_research_expert, delegate_to_math_expert
```

When `handoff_tool_prefix` is `None` (the default), tools are named `transfer_to_<agent_name>`.

## `METADATA_KEY_HANDOFF_DESTINATION`

Every handoff tool carries a special metadata key that LangGraph Supervisor uses internally to identify it as a handoff tool and to extract its target agent:

```python
from langgraph_supervisor.handoff import METADATA_KEY_HANDOFF_DESTINATION
# Value: "__handoff_destination"
```

This metadata is set on each tool returned by `create_handoff_tool`:

```python
handoff_to_agent.metadata = {METADATA_KEY_HANDOFF_DESTINATION: agent_name}
```

At supervisor construction time, `create_supervisor` inspects the `metadata` of every tool in the tools list. Any tool that carries `METADATA_KEY_HANDOFF_DESTINATION` is recognized as a custom handoff tool, allowing the library to skip auto-generating duplicates and to validate that all sub-agents are covered.

<Note>
  If you write a fully custom handoff tool, you must set this metadata key on it so that `create_supervisor` can register it correctly.
</Note>

## The `Command` object

Handoff tools return a LangGraph `Command` object. For a single handoff the tool returns:

```python
Command(
    goto=agent_name,
    graph=Command.PARENT,
    update={**state, "messages": handoff_messages},
)
```

`graph=Command.PARENT` tells LangGraph to apply the command in the parent graph (the supervisor's `StateGraph`) rather than inside the supervisor's own inner ReAct graph. This is what causes routing to jump to the sub-agent node.

## Parallel handoffs

When `parallel_tool_calls=True` is set on `create_supervisor` (supported by OpenAI and Anthropic models), the supervisor LLM can call multiple handoff tools in a single turn, dispatching to several sub-agents concurrently.

```python
workflow = create_supervisor(
    [research_agent, math_agent],
    model=model,
    parallel_tool_calls=True,
)
```

For parallel handoffs, the tool returns a `Command` using `Send` instead of a plain string `goto`:

```python
Command(
    graph=Command.PARENT,
    goto=[Send(agent_name, {**state, "messages": handoff_messages})],
)
```

Each `Send` carries a separate copy of the message history with non-relevant tool calls stripped out. This is handled by the `_remove_non_handoff_tool_calls` helper, which filters the supervisor's last `AIMessage` to retain only the tool call relevant to each specific sub-agent — ensuring that each sub-agent sees a valid, self-consistent message history.

<Info>
  `parallel_tool_calls` defaults to `False`. For models that do not support the `parallel_tool_calls` binding parameter (such as `o3`, `o3-mini`, and `o4-mini`), the setting is silently ignored and tools are bound without it.
</Info>

## Handoff-back messages: `create_handoff_back_messages`

When a sub-agent finishes and control returns to the supervisor, the library optionally inserts a synthetic pair of messages to explicitly mark the transition:

```python
from langgraph_supervisor.handoff import create_handoff_back_messages

ai_msg, tool_msg = create_handoff_back_messages(
    agent_name="math_expert",
    supervisor_name="supervisor",
)
```

The returned tuple contains:

- An `AIMessage` with content `"Transferring back to supervisor"`, a synthetic tool call to `transfer_back_to_supervisor`, and `name=agent_name`.
- A `ToolMessage` with content `"Successfully transferred back to supervisor"`.

Both messages include `response_metadata={"__is_handoff_back": True}` so that downstream code can distinguish them from real agent output.

These messages are appended after the sub-agent's own output messages are selected (according to `output_mode`) and are controlled by the `add_handoff_back_messages` parameter on `create_supervisor`. By default it mirrors `add_handoff_messages`.

## Writing a custom handoff tool

You can replace the default handoff tool entirely. A custom tool must:

1. Accept `state: Annotated[dict, InjectedState]` and `tool_call_id: Annotated[str, InjectedToolCallId]`.
2. Return a `Command` with `graph=Command.PARENT`.
3. Set `metadata = {METADATA_KEY_HANDOFF_DESTINATION: agent_name}` on the tool object.

```python
from typing import Annotated
from langchain_core.tools import tool, BaseTool, InjectedToolCallId
from langchain_core.messages import ToolMessage
from langgraph.types import Command
from langgraph.prebuilt import InjectedState
from langgraph_supervisor.handoff import METADATA_KEY_HANDOFF_DESTINATION

def create_custom_handoff_tool(
    *, agent_name: str, name: str | None, description: str | None
) -> BaseTool:

    @tool(name, description=description)
    def handoff_to_agent(
        task_description: Annotated[
            str,
            "Detailed description of what the next agent should do, "
            "including all of the relevant context.",
        ],
        state: Annotated[dict, InjectedState],
        tool_call_id: Annotated[str, InjectedToolCallId],
    ):
        tool_message = ToolMessage(
            content=f"Successfully transferred to {agent_name}",
            name=name,
            tool_call_id=tool_call_id,
        )
        messages = state["messages"]
        return Command(
            goto=agent_name,
            graph=Command.PARENT,
            update={
                **state,
                "messages": messages + [tool_message],
            },
        )

    handoff_to_agent.metadata = {METADATA_KEY_HANDOFF_DESTINATION: agent_name}
    return handoff_to_agent
```

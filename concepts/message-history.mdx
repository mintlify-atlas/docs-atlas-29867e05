---
title: "Message history"
description: "Control how messages from sub-agents flow into the supervisor's conversation history."
---

As sub-agents complete their work and return control to the supervisor, their output messages need to be merged back into the shared `state["messages"]` list. LangGraph Supervisor gives you fine-grained control over exactly which messages are added and when.

## The `OutputMode` type

The `output_mode` parameter of `create_supervisor` accepts one of two literal values defined by the `OutputMode` type:

```python
OutputMode = Literal["full_history", "last_message"]
```

The default is `"last_message"`.

### `full_history`

When `output_mode="full_history"`, the **entire message history** produced by the sub-agent is appended to the supervisor's state. This includes every intermediate step — tool calls, tool results, and all AI messages — that the sub-agent generated during its run.

```python
workflow = create_supervisor(
    agents=[agent1, agent2],
    model=model,
    output_mode="full_history",
)
```

<Tip>
  Use `full_history` when the supervisor needs to reason over the sub-agent's intermediate steps, or when you want a complete audit trail of what each agent did.
</Tip>

### `last_message`

When `output_mode="last_message"` (the default), only the **final message** from the sub-agent is kept:

- If the last message is a regular `AIMessage`, only that single message is included.
- If the last message is a `ToolMessage`, the two trailing messages (the `AIMessage` that called the tool plus the `ToolMessage` result) are both included, so the message history remains structurally valid.

```python
workflow = create_supervisor(
    agents=[agent1, agent2],
    model=model,
    output_mode="last_message",  # default
)
```

<Tip>
  Use `last_message` to keep the supervisor's context window small. Each sub-agent's internal reasoning is hidden; the supervisor only sees the final answer.
</Tip>

### Tradeoffs

<CardGroup cols={2}>
  <Card title="full_history" icon="list">
    **Pros**
    - Complete visibility into sub-agent reasoning
    - Supervisor can reference intermediate tool results
    - Better for debugging and auditing

    **Cons**
    - Larger context window for the supervisor LLM
    - Higher token cost per turn
    - May introduce noise from unrelated intermediate steps
  </Card>
  <Card title="last_message" icon="message">
    **Pros**
    - Minimal context growth per agent turn
    - Lower token cost
    - Keeps supervisor focused on results, not process

    **Cons**
    - Supervisor cannot see how the sub-agent reached its answer
    - Sub-agent intermediate errors are not visible to the supervisor
  </Card>
</CardGroup>

## Handoff messages

In addition to sub-agent output, LangGraph Supervisor can insert **handoff marker messages** at the boundaries where control transfers between the supervisor and sub-agents. These markers help the LLM understand the structure of the conversation.

### `add_handoff_messages`

When `add_handoff_messages=True` (the default), a pair of `(AIMessage, ToolMessage)` is added to the message history at the moment the supervisor hands off to a sub-agent:

- The `AIMessage` contains the supervisor's tool call requesting the handoff.
- The `ToolMessage` confirms the transfer with content like `"Successfully transferred to <agent_name>"`.

```python
# Default — handoff messages are included
workflow = create_supervisor(
    [research_agent, math_agent],
    model=model,
    add_handoff_messages=True,
)
```

To suppress these messages and keep the history more compact:

```python
workflow = create_supervisor(
    [research_agent, math_agent],
    model=model,
    add_handoff_messages=False,
)
```

### `add_handoff_back_messages`

`add_handoff_back_messages` controls whether a corresponding pair of `(AIMessage, ToolMessage)` is added when the sub-agent **returns control** to the supervisor. It defaults to the same value as `add_handoff_messages`.

```python
workflow = create_supervisor(
    [research_agent, math_agent],
    model=model,
    add_handoff_messages=True,
    add_handoff_back_messages=True,  # defaults to same as add_handoff_messages
)
```

The handoff-back messages are generated by `create_handoff_back_messages` and look like this:

- An `AIMessage` with content `"Transferring back to <supervisor_name>"` and a synthetic tool call.
- A `ToolMessage` with content `"Successfully transferred back to <supervisor_name>"`.

Both messages carry `response_metadata` with the key `__is_handoff_back: True`, which allows downstream code to identify and filter them if needed.

<Note>
  `add_handoff_back_messages` only has an effect when `output_mode` processing is complete and control returns to the supervisor node. Setting it independently from `add_handoff_messages` lets you annotate one direction of the handoff while keeping the other silent.
</Note>

## Configuring each mode

<Tabs>
  <Tab title="Full history + handoff messages">
    ```python
    from langchain_openai import ChatOpenAI
    from langgraph_supervisor import create_supervisor
    from langgraph.prebuilt import create_react_agent

    model = ChatOpenAI(model="gpt-4o")

    workflow = create_supervisor(
        agents=[research_agent, math_agent],
        model=model,
        output_mode="full_history",
        add_handoff_messages=True,
    )
    app = workflow.compile()
    ```
  </Tab>
  <Tab title="Last message only, no handoff messages">
    ```python
    from langchain_openai import ChatOpenAI
    from langgraph_supervisor import create_supervisor

    model = ChatOpenAI(model="gpt-4o")

    workflow = create_supervisor(
        agents=[research_agent, math_agent],
        model=model,
        output_mode="last_message",
        add_handoff_messages=False,
    )
    app = workflow.compile()
    ```
  </Tab>
  <Tab title="Asymmetric handoff annotation">
    ```python
    # Add messages on handoff TO sub-agent, but not on return
    workflow = create_supervisor(
        agents=[research_agent, math_agent],
        model=model,
        add_handoff_messages=True,
        add_handoff_back_messages=False,
    )
    app = workflow.compile()
    ```
  </Tab>

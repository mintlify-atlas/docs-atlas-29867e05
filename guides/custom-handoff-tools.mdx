---
title: "Custom handoff tools"
description: "Customize how the supervisor delegates tasks to sub-agents by building custom handoff tools."
---

By default, `create_supervisor()` automatically generates a handoff tool for each agent using `create_handoff_tool`. These tools follow the naming convention `transfer_to_<agent_name>`. You can customize this behavior in several ways — from renaming the tools to building fully bespoke handoff logic.

## Changing the tool name prefix

The simplest customization is changing the prefix applied to all auto-generated handoff tools via `handoff_tool_prefix`:

```python
workflow = create_supervisor(
    [research_agent, math_agent],
    model=model,
    handoff_tool_prefix="delegate_to_"
)
# Creates tools named: delegate_to_research_expert, delegate_to_math_expert
```

## Using `create_handoff_tool` with custom name and description

For finer control, import `create_handoff_tool` and construct tools manually, then pass them via the `tools` parameter:

```python
from langgraph_supervisor import create_handoff_tool

workflow = create_supervisor(
    [research_agent, math_agent],
    tools=[
        create_handoff_tool(
            agent_name="math_expert",
            name="assign_to_math_expert",
            description="Assign task to math expert"
        ),
        create_handoff_tool(
            agent_name="research_expert",
            name="assign_to_research_expert",
            description="Assign task to research expert"
        ),
    ],
    model=model,
)
```

<Warning>
  When you provide custom handoff tools via `tools`, you must supply one for **every** agent passed to `create_supervisor`. If any agent is missing a corresponding handoff tool, an error is raised at construction time.
</Warning>

## Controlling handoff messages

By default, a pair of `(AIMessage, ToolMessage)` is added to the message history each time a handoff occurs (`add_handoff_messages=True`). You can disable this per-tool:

```python
create_handoff_tool(
    agent_name="math_expert",
    add_handoff_messages=False,
)
```

Or disable it globally for all auto-generated tools via the `create_supervisor` parameter:

```python
workflow = create_supervisor(
    [research_agent, math_agent],
    model=model,
    add_handoff_messages=False,
)
```

## Building a fully custom handoff tool

You can write a handoff tool from scratch when you need to pass extra information to the receiving agent — such as a structured task description. Custom tools must set the `METADATA_KEY_HANDOFF_DESTINATION` metadata key so that `create_supervisor` can identify which agent the tool routes to.

The two injected annotations you need are:

- `InjectedState` — injects the current graph state so you can read the message history or other state fields.
- `InjectedToolCallId` — injects the tool call ID needed to construct a valid `ToolMessage`.

```python
from typing import Annotated

from langchain_core.tools import tool, BaseTool, InjectedToolCallId
from langchain_core.messages import ToolMessage
from langgraph.types import Command
from langgraph.prebuilt import InjectedState
from langgraph_supervisor.handoff import METADATA_KEY_HANDOFF_DESTINATION

def create_custom_handoff_tool(
    *,
    agent_name: str,
    name: str | None,
    description: str | None
) -> BaseTool:

    @tool(name, description=description)
    def handoff_to_agent(
        # Additional arguments the LLM will populate
        task_description: Annotated[
            str,
            "Detailed description of what the next agent should do, "
            "including all of the relevant context."
        ],
        # Injected at runtime — not exposed to the LLM
        state: Annotated[dict, InjectedState],
        tool_call_id: Annotated[str, InjectedToolCallId],
    ):
        tool_message = ToolMessage(
            content=f"Successfully transferred to {agent_name}",
            name=name,
            tool_call_id=tool_call_id,
        )
        messages = state["messages"]
        return Command(
            goto=agent_name,
            graph=Command.PARENT,
            # State update applied to the parent (supervisor) graph
            update={
                "messages": messages + [tool_message],
                "active_agent": agent_name,
                # Pass the task description to the next agent
                # NOTE: individual agents need `task_description` in their state schema
                "task_description": task_description,
            },
        )

    # REQUIRED: lets create_supervisor identify this tool as a handoff
    handoff_to_agent.metadata = {METADATA_KEY_HANDOFF_DESTINATION: agent_name}
    return handoff_to_agent
```

<Note>
  Parameters annotated with `InjectedState` or `InjectedToolCallId` are injected automatically at runtime. They are not included in the tool's JSON schema and will not be seen by the LLM.
</Note>

## Parameter reference

### `create_handoff_tool`

| Parameter | Type | Default | Description |
|---|---|---|---|
| `agent_name` | `str` | — | Name of the agent node to hand off to. |
| `name` | `str \| None` | `None` | Tool name. Defaults to `transfer_to_<agent_name>`. |
| `description` | `str \| None` | `None` | Tool description. Defaults to `Ask agent '<agent_name>' for help`. |
| `add_handoff_messages` | `bool` | `True` | Whether to append handoff `(AIMessage, ToolMessage)` pairs to the message history. |

### `create_supervisor` (handoff-related)

| Parameter | Type | Default | Description |
|---|---|---|---|
| `tools` | `list[BaseTool \| Callable] \| ToolNode \| None` | `None` | Custom tools including handoff tools. If handoff tools are detected here, auto-generation is skipped. |
| `add_handoff_messages` | `bool` | `True` | Global default for handoff message insertion when using auto-generated tools. |
| `handoff_tool_prefix` | `str \| None` | `None` | Prefix for auto-generated handoff tool names. |
